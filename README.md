> 발언자 게임은 [핵심 발언 선별 v4](CHAT-SPEAKER.md)를 적용합니다. 관리자 카톡 메뉴 → 이 말 누가 했게? → `발언자 핵심 문제 생성 (최대 100개)`를 사용하세요. 품질 기준 통과 문제만 자동 출제하며 핵심 발언 1개(예외 2개)를 표시합니다. 나머지 카톡 게임은 [게임별 수동 승인 v3](CHAT-GAME-POLICY.md)를 유지합니다. 로컬 DB 경로는 `.env`의 `CHAT_DATA_DIR`로 고정할 수 있습니다.

# GAPYEONG ARCADE

같은 Wi-Fi에서 5~7명이 즐기는 실시간 파티게임. 노트북은 진행자/전광판, 휴대폰은 참가자입니다. 2명 테스트 모드 제공.

## Windows 실행

Node.js 24 이상과 npm을 설치한 뒤 실행하세요. 카카오톡 분석의 내장 SQLite를 사용합니다.

```powershell
cd D:\workspace\gapyeong-arcade
npm ci
npm run build
$env:NODE_ENV="production"
npm start
```

빌드 후 `start.cmd` 더블클릭으로 실행할 수 있습니다. 개발은 `npm run dev` 또는 `dev.cmd`. 프론트와 서버 모두 3000 포트입니다.

1. 노트북에서 http://localhost:3000 에 접속하여 방을 만듭니다.
2. 같은 Wi-Fi의 스마트폰에서 QR을 스캔하거나 표시된 네트워크 주소로 접속합니다.
3. 네트워크 카드가 여러 개면 진행자 QR 아래 주소 선택에서 올바른 Wi-Fi 주소를 고릅니다.
4. 연결되지 않으면 Windows 방화벽에서 Node.js의 개인 네트워크 연결을 허용하고 공유기의 AP/클라이언트 격리를 확인하세요.
5. 2명 테스트는 서로 다른 기기/브라우저/시크릿 세션으로 참가한 뒤 진행자가 테스트 모드를 켭니다. 같은 브라우저 새로고침은 기존 참가자로 복귀합니다.

외부 서버는 `PUBLIC_URL=https://실제주소`와 필요하면 `PORT`를 설정합니다. 프록시는 WebSocket 업그레이드를 지원해야 합니다. 인터넷 공개 시 TLS와 네트워크 접근 제한을 구성하세요.

## 게임 규칙

카카오톡 TXT 가져오기·통계·검수·새 게임 사용법은 [CHAT-ANALYSIS.md](CHAT-ANALYSIS.md), 실제 성능 및 테스트 결과는 [CHAT-TEST-RESULTS.md](CHAT-TEST-RESULTS.md)를 참고하세요. Host 화면의 **카카오톡 분석 · 문제은행** 메뉴로 시작합니다.

- 스파이: 공통 주제 + 개인 비밀 상황 → 자유 토론 → 투표 → 결과. 입력은 선택 의견만 가능하며 필수가 아닙니다. 정확한 투표 +100, 스파이 생존 +200점, 공동 최다 득표 검거 규칙은 유지합니다.
- 양세찬: TV + 휴대폰으로 진행합니다. 참가자 5~7명 입장 → Host가 양세찬 시작 → 주제 선택. 휴대폰은 타인의 제시어를 기본 공개하고 본인 것은 서버에서 제외합니다. TV 공개/가리기는 독립적입니다. 다음 문제·주제 재설정·취소와 기존 TV 단독 모드를 지원합니다. [진행 안내](YANG-TV.md)
- 친구 재판: 익명 투표 → 내가 최다 득표자인지 이진 예측 → 공개. 제출한 예측이 맞으면 150점, 오답·미제출 0점. 최다 득표 도전 성공자가 있으면 성공자만 벌칙 면제하고, 없으면 최다 득표자와 잘못 도전한 사람이 벌칙입니다. 벌칙과 점수는 별도입니다. [최종 규칙·검증](COURT-RULES.md)을 참고하세요.
- 그림: 정답 순서대로 150/125/100/75/50/40점. 화가는 정답자당 40점. 띄어쓰기를 무시하고 유니코드 정규화 후 정확히 비교합니다. 정답 메시지는 다른 사람에게 전송하지 않습니다. 모든 화가가 한 번씩 그린 뒤 순서가 반복됩니다.
- 숫자: 같은 숫자는 전원 탈락. 유효 숫자 중 목표에 가장 가까운 사람 각 150점, 나머지 유효 참가 40점. 같은 거리는 공동 우승. 전원 중복 또는 미제출은 무승부입니다.
- 미제출: 기권. 답변/투표 생략, 예측/숫자 0점. 타이머는 서버 기준으로 자동 진행합니다. 조기 결과 공개는 남은 단계를 마감합니다.
- 종합은 원점수 누적, 동점은 공동 순위. 마지막 라운드 후 진행자가 최종 시상식을 열면 공동 우승자와 꼴찌가 전원 화면에 공개됩니다.
- 이탈 시 진행자가 대기/계속 진행/라운드 제외를 선택합니다. 대기 중 입력과 그림은 잠깁니다. 화가 또는 스파이를 제외하거나 활성 인원이 2명 미만이면 라운드는 점수 없이 취소됩니다.
- 질문 건너뛰기는 라운드 중단 후 재시작합니다. 풀을 소진하기 전 질문은 반복하지 않습니다. 점수 수정·단계 마감·공개·중단·초기화에는 확인 절차가 있습니다.

## 게임쇼 확장 기능

- **랜덤 게임 룰렛:** 라운드 사이 진행자의 `랜덤 게임 룰렛`으로 추첨합니다. 서버가 4개 게임 중 하나를 같은 확률로 선정하고 전원에게 같은 결과를 전달합니다. 3.6초 연출 중에는 시작/재추첨을 서버에서도 차단합니다. 멈춘 뒤 시작 버튼을 누르면 서버가 선정한 게임으로 시작합니다. 클라이언트가 다른 게임을 요청해도 바꿀 수 없습니다.
- **순위 역전:** 라운드 점수 적용 전후의 공동 순위를 서버가 비교합니다. 순위가 상승한 참가자는 진행자 전광판에 4.2초간 표시되고 순위표가 이동합니다. 재접속으로 과거 결과를 처음 수신하면 효과와 공개 사운드를 재생하지 않습니다.
- **결과 PNG:** 최종 시상식의 `최종 결과 PNG 저장`으로 우승자·꼴찌·전체 점수표를 기기에 저장합니다. 공동 우승/꼴찌와 동점 순위를 모두 포함합니다. 모바일에서 다운로드가 제한되면 미리보기 이미지를 길게 눌러 저장할 수 있습니다. 이미지 생성은 브라우저 내부에서 처리하며 업로드하지 않습니다.
- **AI 친구 멘트:** API 호출 없이 서버가 해당 라운드의 최고 획득 점수, 중복 탈락, 무득점 결과를 바탕으로 템플릿 멘트를 생성합니다. 모든 참가자에게 같은 멘트를 표시합니다.
- **효과음:** 상단 `효과음 켜기`를 기기마다 한 번 눌러 활성화합니다. 기본은 음소거입니다. 정답/오답, 마지막 5초 타이머, 결과 공개, 전광판 역전에 Web Audio 합성음을 사용합니다. 외부 음원이나 API는 필요 없습니다. 여러 휴대폰에서 소리가 겹치지 않게 노트북만 켜는 것을 권장합니다. 무음 전환은 언제든 가능합니다.
- **히든 이벤트:** 기본 OFF입니다. 진행자가 라운드 사이 켜면 3·9·15…라운드는 점수 2배, 6·12·18…라운드는 자유 참여 돌발 미션입니다. 서버가 라운드 시작 때 이벤트를 고정합니다. 2배는 기본 게임 판정과 원점수 계산 이후 한 번만 적용하고 원점수를 결과에 보존합니다. 미션에는 추가 점수/벌점이 없습니다. 점수 수동 수정에는 배수가 적용되지 않습니다. 중단된 라운드도 시작한 라운드 수에는 포함됩니다.

### 확장 검증

`npm test`는 기존 게임, 이벤트 주기·배수 중복 방지, 공동 순위·역전, 룰렛 잠금과 서버 선정 강제를 검증합니다. `npm run test:network`는 별도 운영 서버를 3103 포트에서 시작하여 7인 접속과 관리 권한을 검증하고 종료합니다.

## 개발자 테스트 및 Bot

1. 실행 중인 운영 서버를 종료하고 `npm run dev` 또는 `dev.cmd`로 개발 서버를 시작합니다. 이 명령이 `NODE_ENV=development`를 설정합니다.
2. 노트북에서 방을 만들고 Host 화면의 **개발자 테스트 열기 → 개발자 권한 활성화**를 누릅니다.
3. **새 탭**에서 같은 주소로 들어가 실제 플레이어 1명으로 참가합니다. Host와 참가자는 서로 다른 탭을 사용합니다.
4. Host 테스트 패널에서 1~6명의 Bot을 추가합니다. 전체 정원은 7명이며 개발자 테스트를 켜면 최소 1명부터 시작할 수 있습니다. 1명+Bot6이면 기존 정원 그대로 모든 게임을 검증할 수 있습니다.
5. 평소와 같은 게임 선택·시작·단계 진행·결과 공개·다음 라운드 버튼을 사용합니다. 스파이 토론 단계는 진행자가 다음 단계로 넘깁니다. 각 게임 종료 후 최종 시상식까지 진행할 수 있습니다.

### 테스트 패널

- 자동 플레이 ON/OFF, 응답 지연 0~10000ms, 공개 테스트 도형 정답률 0~100%를 설정합니다.
- Bot마다 랜덤 닉네임·고유 ID·아바타가 있으며, 일반 참가자와 **동일한 `playerAction` → `submit` 및 점수 엔진**을 사용합니다.
- Bot은 자신의 `view(room, botId)`에 포함된 질문과 정보만 읽습니다. 다른 참가자의 역할·정답·비밀 선택을 직접 읽지 않습니다.
- Bot 화가는 공개 도형 사전의 테스트 패턴을 Canvas 획으로 전송합니다. 이 도형은 그림 동기화/정답 흐름 검증용입니다. Bot 추측자는 공개된 획을 인식한 경우에만 설정 정답률을 적용합니다. 사람의 자유 그림에는 사전 단어로 랜덤 추측하며, 비밀 정답을 읽어 정답률을 강제하지 않습니다.
- 자동 플레이 OFF에서는 Bot을 선택하여 답변·투표·예측·숫자·정답을 수동 입력합니다. `선택 Bot 기본 행동 1회 실행`은 현재 단계에 맞는 랜덤 행동 또는 화가 테스트 도형을 전송합니다. Bot 본인에게 허용된 화면 상태도 확인할 수 있습니다.
- `모든 Bot 즉시 응답`은 지연을 생략하되, 응답 누락/연결 끊김/이미 제출/타이머 만료/일시정지와 정상 제출 검증을 그대로 적용합니다.
- 특정 Bot의 응답 누락, 연결 해제/복구, 현재 타이머 1초 단축, 참가자 점수 수정, 테스트 방 초기화를 제공합니다. 초기화는 참가자를 유지하며 점수·라운드·누락 설정을 초기화하고 Bot 접속을 복구합니다.
- 최근 150개 서버 이벤트와 현재 단계·제한시간·접속·제출·점수를 확인할 수 있습니다. 로그에는 투표 대상이나 비밀 제시어를 기록하지 않습니다.
- 반응시간은 단계 시작부터 정상 Bot 행동까지의 서버 기준 경과 ms로 기록합니다. 기존 네 게임의 점수 계산은 변경하지 않습니다.

### 권한 및 운영 환경

`NODE_ENV`가 정확히 `development`일 때만 개발자 서버 모듈을 불러옵니다. Host 접속 권한에 더해 별도로 발급된 개발자 capability가 있어야 테스트 명령을 사용할 수 있습니다. 일반 참가자는 개발 환경에서도 호출할 수 없습니다. 운영 환경은 모든 `debug:*` 요청을 서버에서 거부하고 관리자 메뉴·디버그 상태를 보내지 않습니다. `start.cmd`는 `NODE_ENV=production`을 설정합니다. 개발자 권한은 새로고침 후 다시 활성화합니다.

### 독립 세션 및 E2E

참가자 토큰을 **탭별 sessionStorage**에 저장합니다. 같은 브라우저에서 주소를 직접 연 새 탭도 독립 참가가 가능하며, 탭 새로고침과 일시 연결 해제는 기존 ID로 복구됩니다. 탭 복제나 저장소 복사는 같은 토큰을 복사할 수 있어 새 접속이 이전 접속을 종료합니다. 새 참가자는 주소를 직접 연 새 탭/시크릿 창/다른 브라우저를 사용하세요. 탭을 닫으면 접속 정보가 소실될 수 있습니다.

Playwright는 별도 개발 서버(3101)와 운영 서버(3102)를 자동 실행하고 종료합니다. 이미 사용 중인 3000 포트 서버는 건드리지 않습니다. E2E는 다음을 검증합니다.

1. 같은 브라우저의 새 탭 독립 참가 및 새로고침 복원.
2. 관리자 UI를 통한 수동 제출, 중복 거부, 누락, Bot 연결 복구, 타이머 마감, 점수 변경, 초기화.
3. Host + **독립 Chromium BrowserContext 7개**에서 실제 참가자 7명 접속, 4개 게임, 실시간 동기화, 새로고침, 네트워크 이탈/복구, 최종 랭킹 및 PNG 저장.
4. 실제 참가자 1명 + Bot6명 자동 행동으로 4개 게임과 최종 시상식, 최종 랭킹 콘솔 출력.
5. 운영 서버 UI 미노출 및 직접 개발자 요청 거부.

HTML 결과는 `playwright-report/index.html`, 스크린샷과 결과 PNG는 `test-results/`에 저장합니다. 실패 시 trace를 보존합니다. 테스트별 난수 게임이라 최종 우승자는 실행마다 달라집니다.

이번 실제 실행 결과와 최종 순위 예시는 [TEST-RESULTS.md](TEST-RESULTS.md)에 기록했습니다.

## 운영 범위

방과 토큰, 점수는 서버 메모리에 저장됩니다. **서버가 종료되면 방과 점수는 사라집니다.** 단일 Node 프로세스로 실행하세요. 브라우저 새로고침과 일시 연결 끊김은 복구합니다. 같은 토큰의 새 연결은 이전 연결을 종료합니다. 생성 후 24시간이 지난 미접속 방은 정리됩니다.

`package-lock.json`에 설치 버전을 고정했습니다. 현재 작업 환경에는 npm 명령이 없어 `package/`에 npm 부트스트랩을 준비했습니다. 일반 Windows에서는 설치된 npm을 사용하세요. `package/`와 `npm.tgz`는 배포할 필요가 없습니다.

## 실제 데이터 검증

실제 TXT의 로컬 검증, 분할 내보내기 묶음, Host 원본 비교 화면, 통계 재대조, 승인 전 미리보기와 결과 확인 방법은 [CHAT-VALIDATION.md](CHAT-VALIDATION.md)에 정리했습니다.

```powershell
npm run test:chat-real -- data/kakao --collection
```

`--collection`은 같은 내보내기의 분할 파일임을 확인한 폴더에만 사용하세요. 실제 원본·SQLite·결과 보고서는 `data/`에 보관하고 Git에서 제외합니다. 실제 참가자 매핑은 Host가 확인합니다. 맥락 엔진의 품질 기준을 통과한 문제는 개별 승인 없이 출제됩니다.

## 맥락 기반 자동 문제은행

매핑 확인창의 값 유실과 API 예외 처리를 수정했습니다. 기존 DB는 통계 분석 후 **8종 문제 후보 생성**을 다시 실행하면 품질 기준을 통과한 문제를 개별 승인 없이 사용할 수 있습니다. 마음에 들지 않는 문제만 제외하세요. 구간 설정, 자동 상태, 익명 대화 표시, 실제 50문제 비교와 검증 방법은 [CHAT-CONTEXT.md](CHAT-CONTEXT.md)를 참고하세요.

## 기본 질문 제외·복구

친구 재판·스파이 결과에서 Host의 `🚫 이 질문 다시 나오지 않게 제외`를 누르면 모든 방의 다음 출제부터 제외합니다. `📚 기본 게임 질문 관리 열기`에서 목록·검색·복구가 가능합니다. 스파이는 세트 전체를 관리하며 진행 중 목록은 차단됩니다. 제외는 별도 SQLite에 영구 저장되고 전체 게임 초기화 후에도 유지됩니다. 같은 세션의 질문은 반복하지 않으며, 재판·스파이·그림 질문 소진 시 전체 초기화가 필요합니다. [설계·테스트·저장 경로](QUESTION-BANK.md)를 참고하세요.
